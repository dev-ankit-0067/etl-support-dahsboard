# 01 · Architecture

## 1. High-level topology

```
                    ┌────────────────────────────────────────────────────┐
                    │                    Browser                          │
                    │           React dashboard (SPA)                     │
                    └───────────────────────┬────────────────────────────┘
                                            │  HTTP  /  and  /api/*
                                            ▼
                    ┌────────────────────────────────────────────────────┐
                    │                      nginx :80                      │
                    │   /api/  ─────────────►  FastAPI backend :8080      │
                    │   /      ─────────────►  Vite preview  :3000        │
                    └───────────────┬─────────────────────┬──────────────┘
                                    │                     │
              ┌─────────────────────▼───┐        ┌────────▼──────────────┐
              │  FastAPI  (aws-backend)  │        │  Vite preview server  │
              │  Python 3.12 / uvicorn   │        │  serves built SPA     │
              └───────────┬──────────────┘        └───────────────────────┘
                          │
      ┌───────────────────┼──────────────────────────────────────────┐
      ▼            ▼      ▼          ▼            ▼            ▼        ▼
   AWS Glue   AWS Lambda CloudWatch Cost        Budgets/STS  Jira    HuggingFace
   (jobs/     (metrics)  Logs       Explorer                Cloud    Inference
    runs)                & Metrics  (costs)                 (issues) (LLM agents)
```

- **nginx** (`nginx/default.conf`) is the single public entry point. It routes `/api/` to the
  FastAPI backend and everything else to the frontend preview server.
- The Vite dev server also has its own proxy (`vite.config.ts` → `server.proxy["/api"]` →
  `http://localhost:8080`), so `pnpm --dir artifacts/etl-dashboard run dev` works without nginx.

## 2. The "two backends" model

This repo contains **two independent server implementations that share one URL surface**:

| | `aws-backend` (FastAPI) | `artifacts/api-server` (Express) |
|---|---|---|
| Language | Python 3.12 | TypeScript / Node 24 |
| Purpose | **Production backend** — real AWS + Jira + LLM data | Mock/contract server with static data |
| Data | Live: Glue, Lambda, CloudWatch, Cost Explorer, Jira, HuggingFace | Hard-coded JSON fixtures |
| Started by | `startup.sh` (port 8080) | `pnpm --filter @workspace/api-server run dev` |
| Docs | [02-backend-python.md](./02-backend-python.md) | [03-backend-express.md](./03-backend-express.md) |

The **OpenAPI spec** (`lib/api-spec/openapi.yaml`) is the shared contract. Orval generates the
frontend's React-Query hooks and Zod schemas from it. The Express server implements the spec's
endpoints with fixtures; the FastAPI server implements a superset (it also adds `/logs/*`,
`/agent/*`, `/agents/*`, `/lambdas/*`, and `/costs/service-trend`, which are not in the spec and are
called by the frontend via plain `fetch`).

> **Important nuance:** `startup.sh` runs the **FastAPI** backend on 8080, so in the shipped runtime
> the Python backend is authoritative. The Express server is primarily a UI-development convenience
> and a live reference implementation of the OpenAPI contract.

## 3. Request-flow examples

### A page using a generated hook (contract endpoint)
`executive-overview.tsx` calls `useGetOverviewKpis()` (generated by Orval).
→ `customFetch("/api/overview/kpis")` → nginx → FastAPI `overview.router` → `glue_service` +
`incidents_service` (MCP → Jira/ServiceNow per `INCIDENT_PROVIDER`, overridable at runtime via the
remote S3 config document — see `remote_config.py`) → cached calls → `OverviewKpis` JSON.

### A page using a raw fetch (non-contract endpoint)
`costs.tsx` does `fetch("/api/costs/service-trend")` directly (not in the OpenAPI spec).
→ FastAPI `costs.router` → `costs_service.service_trend()` → Cost Explorer per-service trends.

### An AI agent flow
The **RCA Analysis** / **Log ticket** buttons → `POST /api/agents/analyze` with a resource identifier
(and `resource_type`) → FastAPI `agents.router` → `agent_service.run_log_analysis_agent()` /
`run_jira_creation_agent()` → a LangChain tool-calling agent fetches the logs itself (Glue/Lambda/
EMR/EMR-Serverless via CloudWatch, or S3 via `fetch_s3_logs`), the HuggingFace LLM produces a
structured RCA, and for the ticket flow `create_incident_ticket` opens a ticket via the configured
incident provider (Jira/ServiceNow through the MCP layer). See
[02-backend-python.md](./02-backend-python.md#ai-agents).

## 4. Monorepo layout & build

- **pnpm workspaces** (`pnpm-workspace.yaml`) groups `artifacts/*`, `lib/*`, and `scripts`.
- A **package catalog** pins shared dependency versions (React 19.1.0, Vite 7, Tailwind 4, etc.).
- A **supply-chain guard** (`minimumReleaseAge: 1440`) blocks npm packages younger than 1 day.
- TypeScript project references: `tsconfig.base.json` → per-package `tsconfig.json`; the root
  `pnpm run typecheck` builds the libs (`tsc --build`) then typechecks each artifact.
- The frontend builds with Vite; the Express server builds a single ESM bundle with esbuild
  (`build.mjs`); the Python backend is packaged with the `aws-backend/Dockerfile`.

## 5. Data-shape contract

The Pydantic models in `aws-backend/app/models/*` and the OpenAPI component schemas in
`openapi.yaml` are intentionally kept in sync so the same JSON satisfies the generated TypeScript
types. Field names use **camelCase** end-to-end (e.g. `totalPipelines`, `costPerRun`,
`slaCompliancePercent`) even though the Python code is otherwise snake_case, because the frontend
consumes them directly.

## 6. Cross-cutting concerns

| Concern | Frontend | FastAPI backend | Express backend |
|---------|----------|-----------------|-----------------|
| Logging | Runtime error overlay (Replit plugin) | JSON logs (`python-json-logger`) | `pino` / `pino-http` (pretty in dev) |
| Caching | React Query cache + `refetchInterval` | TTL buckets (`cachetools`) short/medium/long | none (static) |
| Errors | Toasts + error states in modals | Global exception handlers → JSON error envelopes | per-route |
| CORS | — | `CORSMiddleware` (configurable origins) | `cors()` (open) |
| Auth | Cognito login gate (`AuthContext`), ID token as bearer on every call; silent refresh + redirect-to-login on expiry/401 | Cognito JWT verified on all `/api/*` except `/config` (`require_auth`) | none |
